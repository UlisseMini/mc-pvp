Whose tick?

A local player owns a position, a bounding box, and three stored motion components. Position is in blocks. Motion is in blocks per movement tick. An ordinary game tick targets 50 ms. The server and the two clients each advance their own counters. Two events called “tick 100” on different machines have no shared timing guarantee, even on localhost.

  1. Attacker’s clientPicks an entity with the current ray, consumes attack presses, sends an attack, and runs the local attack response.
  2. ServerProcesses movement, sprint actions and attacks in queue order. Its view of both players determines damage and outgoing velocity.
  3. Victim’s clientApplies the velocity packet on its game thread. The next local move can spend it immediately, or a local action can modify it first.

An ordinary local tick, zoomed in

The game loop drains scheduled tasks before running the ticks due that frame. In a local tick, Minecraft refreshes the aimed target, consumes queued presses, then updates entities. The local player samples movement keys, resolves sprint, moves, and reports changed sprint/sneak state and movement. The remote replica advances during its own entity update. Rendering blends the completed updates using the partial tick.

Here is the part that determined your first displacement in m2151. self is the local player, replica is its local copy of the opponent, and packet holds the three signed S12 velocity components.

static Move firstMove(Player self, Player replica, short[] packet, boolean entityContact) {
    self.motion = decodeVelocity(packet);
    if (entityContact) consumeClick(self, Ray.ENTITY, replica);

    Keys keys = W_AND_SPRINT;
    Input input = sampleInput(self, keys);
    updateSprint(self, keys, input);
    Move move = travel(self, input, keys.jump(), 0.6f, List.of(FLOOR));
    self.airAcceleration = self.sprinting ? SPRINT_AIR : 0.02f; // After travel
    return move;
}

The render loop can also refresh the ray. A frame can run zero, one, or several logic ticks. A packet’s wire arrival, its main-thread handler return, and the first movement using its value are three different timestamps. On the server, accepted position reports move and validate a player. Other entities, server timers and tracking have their own updates. Replaying one client’s key schedule as if it were the server’s clock gives a different exchange.

From keys to acceleration

static Input sampleInput(Player p, Keys keys) {
    float forward = (keys.w() ? 1 : 0) - (keys.s() ? 1 : 0);
    float strafe  = (keys.a() ? 1 : 0) - (keys.d() ? 1 : 0);
    if (keys.sneak()) { forward *= 0.3; strafe *= 0.3; }
    if (p.usingItem)  { forward *= 0.2f; strafe *= 0.2f; }
    return new Input(strafe, forward);  // Sprint reads these before the 0.98 damping.
}
Read the sprint eligibility and double-tap checks
static void updateSprint(Player p, Keys keys, Input input) {
    if (p.sprintTicks > 0 && --p.sprintTicks == 0) p.sprint(false);
    if (p.tapTicks > 0) p.tapTicks--;
    if (p.usingItem) p.tapTicks = 0;

    boolean forward = input.forward() >= 0.8f;
    boolean canStart = forward && p.food > 6 && !p.usingItem && !p.blind;
    boolean risingTap = p.grounded && !p.previousSneak && p.previousForward < 0.8f;
    if (!p.sprinting && canStart) {
        if (keys.sprint() || (risingTap && p.tapTicks > 0)) p.sprint(true);
        else if (risingTap) p.tapTicks = 7;
    }
    if (p.sprinting && (!forward || p.hitWall || p.food <= 6)) p.sprint(false);
    p.previousForward = input.forward();
    p.previousSneak = keys.sneak();
}

In an ordinary survival duel, forward input of at least 0.8, food above 6, and no item use or Blindness allow the sprint key to start sprinting. The alternate double-tap branch uses a rising forward input on the ground and a seven-tick timer. The held sprint-key branch can re-arm in the air. Falling below the forward threshold, insufficient food, or a horizontal collision cancels an active sprint. The flight permission bypasses the hunger gate. Releasing the sprint key alone can leave an existing sprint active.

The client’s sprint-duration timer is set to 600 ticks on sprint start and counts down. At expiry the flag clears; holding the eligible sprint bind can start it again. Sprint eligibility uses the sampled forward amount before the later 0.98 input multiplier.

Three sprint states matter. Your local flag changes local speed and attack drag. Your client also remembers the last flag it sent to the server. The server has its own flag, which an accepted sprint attack can clear. At the walking-report phase, the client sends START or STOP only when its local flag differs from its remembered value. A contact can clear local sprint and held Ctrl can restore it before this comparison. That sequence can send neither transition. A W-tap works when the released and re-pressed inputs survive sampling and the renewed START reaches the server before the intended attack.

On ground, a player reads the current movement-speed attribute on that tick, ordinarily 0.1 walking and about 0.13 sprinting. Speed effects and attribute modifiers change this value. In air, travel reads jumpMovementFactor. The player refreshes this after travel, ordinarily to 0.02 or about 0.026. Starting a sprint in midair can give walking air acceleration for one more movement.

The dry-land travel loop

Track both displacement on this move and motion saved for the next move. The player first accelerates and moves. Horizontal friction and vertical drag usually change the value carried out of that move.

static Move travel(Player p, Input input, boolean jump, float slip, List<Box> solids) {
    Vec v = p.motion;
    v = new Vec(cutoff(v.x), cutoff(v.y), cutoff(v.z));
    if (p.jumpTicks > 0) p.jumpTicks--;
    if (!jump) p.jumpTicks = 0;
    if (jump && p.grounded && p.jumpTicks == 0) {
        v = new Vec(v.x, 0.42f, v.z); // No Jump Boost in this example.
        if (p.sprinting) v = v.plus(jumpImpulse(p.yaw));
        p.jumpTicks = 10;
    }
    float friction = p.grounded ? 0.91f * slip : 0.91f;
    float groundSpeed = p.sprinting ? SPRINT_GROUND : 0.1f;
    float acceleration = p.grounded
            ? groundSpeed * (0.16277136f / (friction * friction * friction))
            : p.airAcceleration;

    Vec request = v.plus(accelerate(input, p.yaw, acceleration));
    Path path = moveBox(p.box, request, p.grounded, solids);
    Vec d = path.displacement();
    p.box = path.box();
    p.grounded = request.y < 0 && request.y != path.collisionY();
    p.hitWall = request.x != d.x || request.z != d.z;
    double vy = request.y == path.collisionY() ? request.y : 0; // Ordinary landing
    p.motion = new Vec(request.x == d.x ? request.x * friction : 0,
                       (vy - 0.08) * 0.98f,
                       request.z == d.z ? request.z * friction : 0);
    return new Move(d, p.motion, p.grounded);
}
Read the input normalization and yaw rotation
static Vec accelerate(Input input, float yaw, float acceleration) {
    float s = input.strafe() * 0.98f, w = input.forward() * 0.98f;
    float squared = s*s + w*w;
    if (squared < 0.0001f) return ZERO;
    float scale = acceleration / Math.max(1f, (float)Math.sqrt(squared));
    s *= scale;
    w *= scale;
    float radians = yaw * (float)Math.PI / 180f;
    float sin = sinTable(radians), cos = cosTable(radians);
    return new Vec(s*cos - w*sin, 0, w*cos + s*sin);
}

Yaw 0 faces +Z; yaw −90° faces +X. W alone enters at 0.98, below the normalization threshold, giving about 0.098 ground acceleration walking or 0.1274 sprinting on ordinary blocks. W+A exceeds length 1 and gets normalized to length 1. Diagonal input therefore gives a small magnitude difference versus cardinal input; it also splits the acceleration across different axes. Mouse yaw rotates the new acceleration. Existing momentum keeps its world direction.

Friction is a retention factor. Ordinary block slipperiness is 0.6f, so ground retains about 0.54600006 of horizontal motion per move. Air retains about 0.91. Ice slipperiness is 0.98f, giving about 0.8918 ground retention. Ice also reduces the input acceleration through 1/f³. Both effects belong in an ice calculation. On solid ground the lookup uses the block at (floor(x), floor(box.minY)−1, floor(z)). The block under the center can differ from the block supporting one corner at a ledge.

Three sprint steps from rest. On an ordinary floor with W and sprint held, the first displacement is 0.127400 and the stored speed is 0.069560. The second displacement is about 0.196960 and stored speed is about 0.10754. The third displacement is about 0.23494. Eventually displacement approaches 0.1274 / (1−0.546) ≈ 0.28062 blocks/tick, about 5.61 blocks/second at 20 TPS. Releasing W removes subsequent forward acceleration. Existing speed still moves you and then decays. Values below the 0.005 per-axis cutoff are cleared before travel.

Jump and land on different branches. Jump sets Y speed to the widened float near 0.42, plus 0.1 per Jump Boost level. Sprint-jump adds 0.2 horizontally in the facing direction. A held jump has a ten-tick repeat gate; the counter decrements on living updates, and releasing jump clears it. The launch can start with onGround=true, so its first horizontal move uses ground acceleration and retention. A landing move begins in the air and uses air retention even after the floor clips Y. The following move gets ground control. Standing still on a solid floor repeatedly ends with about −0.0784 stored Y. Next time, the floor clips that attempted downward motion to zero again.

const f32 = Math.fround;
function initialState(mode) {
    const hit = mode === 'ground' || mode === 'air';
    const grounded = mode !== 'air';
    const retention = f32(f32(0.6) * f32(0.91));
    const settledSprintMotion = 0.1274 * retention / (1 - retention);
    return { x: 0, y: grounded ? 0 : 0.586973, grounded,
        vx: hit ? -0.527375 : mode === 'release' ? settledSprintMotion : 0,
        vy: hit ? 0.361375 : -0.08 * f32(0.98) };
}
function moveOneTick(before, mode, tick, contact) {
    const hit = mode === 'ground' || mode === 'air';
    const sprint = mode !== 'walk' && mode !== 'release';
    const slipperiness = f32(mode === 'ice' ? 0.98 : 0.6);
    const friction = before.grounded ? f32(slipperiness * f32(0.91)) : f32(0.91);
    const cube = f32(f32(friction * friction) * friction);
    const groundSpeed = f32(sprint ? 0.13000001 : 0.1);
    const airSpeed = f32(sprint ? 0.02599999867 : 0.02);
    const acceleration = before.grounded ? f32(groundSpeed * f32(f32(0.16277136) / cube)) : airSpeed;
    const forward = f32(mode === 'release' ? 0 : 0.98);
    let vx = before.vx, vy = before.vy;

    if (hit && tick === 1 && contact) vx *= 0.6;
    if (Math.abs(vx) < 0.005) vx = 0;
    if (Math.abs(vy) < 0.005) vy = 0;
    if (mode === 'jump' && tick === 1) {
        vy = f32(0.42);
        vx += f32(0.2);
    }
    const inputX = f32(forward * acceleration); // Facing +X, always W or idle.
    const dx = vx + inputX;
    const dy = Math.max(-before.y, vy);         // Solid plane at Y=0.
    const grounded = vy < 0 && dy !== vy;
    return { x: before.x + dx, y: before.y + dy, grounded,
        vx: dx * friction, vy: ((grounded ? 0 : vy) - 0.08) * f32(0.98),
        dx, dy, friction, inputX, entryGround: before.grounded };
}
function trajectory(mode, contact) {
    const rows = [initialState(mode)];
    for (let tick = 1; tick <= 20; tick++) rows.push(moveOneTick(rows[tick-1], mode, tick, contact));
    return rows;
}

How the box meets the floor

The normal standing player has an axis-aligned box about 0.6 blocks wide and 1.8 tall. Position is the midpoint of the box in X/Z and the bottom in Y. The collision routine gathers solid boxes intersecting the player’s swept volume. For ordinary movement it reduces the requested Y offset to whatever fits, offsets the box in Y, and repeats for X, then Z. Resolving axes in sequence lets you slide along a wall and makes corners sensitive to the axis order.

static Path slide(Box box, Vec request, List<Box> solids) {
    double y = clip(Axis.Y, box, request.y, solids);
    box = box.offset(0, y, 0);
    double x = clip(Axis.X, box, request.x, solids);
    box = box.offset(x, 0, 0);
    double z = clip(Axis.Z, box, request.z, solids);
    return new Path(box.offset(0, 0, z), new Vec(x, y, z), y);
}
Read axis clipping and the two step-up paths
static double clip(Axis axis, Box b, double amount, List<Box> solids) {
    for (Box s : solids) {
        boolean overlapX = b.x1 > s.x0 && b.x0 < s.x1;
        boolean overlapY = b.y1 > s.y0 && b.y0 < s.y1;
        boolean overlapZ = b.z1 > s.z0 && b.z0 < s.z1;
        double low, high, obstacleLow, obstacleHigh;
        switch (axis) {
            case X -> {
                if (!overlapY || !overlapZ) continue;
                low = b.x0; high = b.x1; obstacleLow = s.x0; obstacleHigh = s.x1;
            }
            case Y -> {
                if (!overlapX || !overlapZ) continue;
                low = b.y0; high = b.y1; obstacleLow = s.y0; obstacleHigh = s.y1;
            }
            default -> {
                if (!overlapX || !overlapY) continue;
                low = b.z0; high = b.z1; obstacleLow = s.z0; obstacleHigh = s.z1;
            }
        }
        if (amount > 0 && high <= obstacleLow) amount = Math.min(amount, obstacleLow-high);
        if (amount < 0 && low >= obstacleHigh) amount = Math.max(amount, obstacleHigh-low);
    }
    return amount;
}

static Path moveBox(Box start, Vec request, boolean grounded, List<Box> solids) {
    Path plain = slide(start, request, solids);
    Vec d = plain.displacement();
    boolean landed = request.y < 0 && d.y != request.y;
    if ((!grounded && !landed) || (d.x == request.x && d.z == request.z)) return plain;

    Box swept = start.sweptXZ(request.x, request.z);
    Path wide = stepPath(start, swept, request, solids);
    Path narrow = stepPath(start, start, request, solids);
    Path best = wide.horizontalSquared() > narrow.horizontalSquared() ? wide : narrow;
    return best.horizontalSquared() > plain.horizontalSquared() ? best : plain;
}

static Path stepPath(Box start, Box clearance, Vec request, List<Box> solids) {
    double up = clip(Axis.Y, clearance, 0.6f, solids);
    Path across = slide(start.offset(0, up, 0), new Vec(request.x, 0, request.z), solids);
    double down = clip(Axis.Y, across.box(), -up, solids);
    Vec d = across.displacement();
    return new Path(across.box().offset(0, down, 0), new Vec(d.x, up+down, d.z), down);
}

A normal player can step up about 0.6 blocks. A half slab can therefore be traversed without an explicit jump. The floor can support any overlapping part of the footprint. On the last platform block, a player’s center can pass the edge by almost 0.3 blocks and still have support. In this lab’s 10-block sumo arena, the top is Y=12 and the referee declares a fall once feet fall below Y=11.5. Crossing the last block’s center, losing support, starting to descend, and scoring the ring-out can all happen at different times.

What a click actually does

There are three counts worth keeping separately: physical presses, local entity contacts, and accepted server hits. Minecraft can consume several queued presses before one move. Aiming through air, aiming at a block, the miss counter, and aiming at a player take different branches.

static void consumeClick(Player self, Ray ray, Player replica) {
    if (self.leftClickCounter > 0) return;
    self.swingCount++;
    if (ray == Ray.MISS) self.leftClickCounter = 10;
    if (ray != Ray.ENTITY) return; // Block interactions use a different path.

    self.attackPackets++; // C02 ATTACK is queued before the local hit.
    int levels = self.knockbackLevel + (self.sprinting ? 1 : 0);
    // An ordinary remote player accepts the local damage call.
    if (levels > 0) applyAttackBonus(self, replica, levels);
}

static void applyAttackBonus(Player attacker, Player target, int levels) {
    float radians = attacker.yaw * (float)Math.PI / 180f;
    Vec bonus = new Vec(-sinTable(radians) * levels * 0.5f, 0.1,
                          cosTable(radians) * levels * 0.5f);
    target.motion = target.motion.plus(bonus);
    attacker.motion = attacker.motion.brakeXZ();
    attacker.sprint(false);
}

The remote player class in 1.8.9 returns true from its local damage handler. The attack code can therefore slow the attacker before the server decides whether the target is immune. A hit with no knockback levels skips this drag branch. Repeating raw clicks while sprint remains false cannot produce a second sprint drag. If sprint is re-armed and the ray still hits, another eligible contact can scale X/Z again. Two qualifying contacts with nothing else between the multiplications retain 0.36; three retain 0.216. On real ticks insert acceleration, friction, collision and any replacement velocity between them. Braking a negative X recoil can help hold space; braking positive X pursuit can give it away. Y is unchanged by attacker drag.

Vanilla’s survival MISS branch can set a ten-tick click delay. The block-controller path can clear leftClickCounter when attack is released. An unconditional half-second penalty on every miss gives incorrect timing for short press/release inputs. Read the actual counter at click consumption.

The victim’s damage window

static Damage acceptDamage(Player victim, float incoming) {
    if (victim.hurtResistantTime > victim.maxHurtResistantTime / 2f) {
        if (incoming <= victim.lastDamage) return new Damage(Hit.REJECTED, 0);
        float excess = incoming - victim.lastDamage;
        victim.lastDamage = incoming;
        return new Damage(Hit.UPGRADE, excess);
    }
    victim.lastDamage = incoming;
    victim.hurtResistantTime = victim.maxHurtResistantTime;
    victim.hurtTime = 10;
    return new Damage(Hit.FRESH, incoming);
}

Damage.beforeMitigation is the amount the game passes to its damage routine. A fresh result also triggers the base knockback shown below. The upgrade is the excess damage. It neither renews H nor runs the fresh base-knockback branch. The enclosing attacker code still sees success and may apply the sprint/enchantment bonus, consume sprint and brake the attacker. A new velocity packet depends on the victim’s server velocityChanged flag. An accepted upgrade can send none. The equal-damage fresh window reopens at H ≤ 10 for vanilla (maximum 20), and H ≤ 9 for this lab’s MMC preset (maximum 18). Those are server updates. A red flash or 450 ms on a client clock is an imperfect proxy.

With an ordinary living target, a 1.8.9 critical requires positive attacker fall distance, airborne state, and no ladder, water, Blindness or mount. Sprinting is allowed. The critical multiplies positive base attack damage by 1.5 before enchantment damage is added. For ordinary unenchanted sumo punches this can turn 1 into 1.5 during immunity and explain a damage upgrade. Armor, blocking and other mitigation affect health after acceptance. The training referee can preserve health while recording hits. Receiving a hit starts the victim’s timer; it can still return an attack immediately.

Where knockback comes from

Vanilla 1.8.9

Use two horizontal unit vectors. away is the server position direction from attacker to victim. facing is the direction of the attacker’s server yaw. On a glancing hit these point in different directions. For an ordinary fresh melee hit on a player with zero knockback resistance, the main code path is:

static short[] vanillaHit(Player attacker, Player victim, Vec separation, float damage) {
    Vec saved = victim.motion;
    int levels = attacker.knockbackLevel + (attacker.sprinting ? 1 : 0);
    Hit hit = acceptDamage(victim, damage).kind();
    if (hit == Hit.REJECTED) return null;

    if (hit == Hit.FRESH) {
        Vec away = awayDirection(separation);
        victim.motion = new Vec(saved.x / 2 + away.x * 0.4f,
                                Math.min(0.4f, saved.y / 2 + 0.4f),
                                saved.z / 2 + away.z * 0.4f);
        victim.velocityChanged = true;
    }
    if (levels > 0) applyAttackBonus(attacker, victim, levels);
    if (!victim.velocityChanged) return null;
    short[] packet = encodeVelocity(victim.motion);
    victim.velocityChanged = false;
    victim.motion = saved;
    return packet;
}
Read the direction calculation for overlapping players
static Vec awayDirection(Vec separation) {
    double x = separation.x, z = separation.z;
    while (x*x + z*z < 0.0001) { // Vanilla fallback for overlapping centers
        x = (Math.random() - Math.random()) * 0.01;
        z = (Math.random() - Math.random()) * 0.01;
    }
    float length = (float)Math.sqrt(x*x + z*z);
    return new Vec(x / length, 0, z / length);
}

From zero server motion, a head-on ordinary fresh hit yields about (H=0.4, Y=0.4); a head-on level-one sprint hit gives about (H=0.9, Y=0.5). The server snapshots its own victim motion. Your client may already be moving at a different velocity. Nearly coincident centers trigger a random horizontal direction fallback for vanilla base knockback. Nonzero knockback resistance introduces random checks for the base impulse and for setting the velocity-changed flag. Ordinary unmodified player resistance is zero.

The local MMC-style preset

The lab overrides the outgoing vector at the fresh-player-hit packet construction site. It keeps native client travel, attacker drag and server damage-window logic. This preset is a provisional reconstruction. The public MMC server’s implementation is unverified. The result metadata identifies which local rule a recording used.

static Vec mmcVelocity(Player attacker, Player victim, Vec separation, boolean sprintAtEntry,
                       Landing landing, MmcSettings settings) {
    int levels = attacker.knockbackLevel + (sprintAtEntry ? 1 : 0);
    double angle = Math.toRadians(attacker.yaw);
    double facingX = -Math.sin(angle), facingZ = Math.cos(angle);
    double length = Math.hypot(separation.x, separation.z);
    double awayX = length < 0.01 ? facingX : separation.x/length;
    double awayZ = length < 0.01 ? facingZ : separation.z/length;
    double height = victim.box.y0 - victim.floorY;
    if (height > 0.675) victim.heightCapped = true;

    boolean willLand = landing.supported && landing.hasDelta && !landing.groundedReport
            && predictsLanding(height, landing.lastDeltaY, landing.addedRttMs);
    double y = victim.heightCapped && !willLand ? 0 : 0.361375 + levels * settings.sprintVertical;
    return new Vec((0.5274 * awayX + 0.327 * levels * facingX) * settings.horizontal,
                   y * settings.vertical,
                   (0.5274 * awayZ + 0.327 * levels * facingZ) * settings.horizontal);
}
Read the landing prediction
static boolean predictsLanding(double height, double dy, double rttMs) {
    if (height <= 0 || height > 1.3 || rttMs <= 25) return false;
    int ticks = (int)Math.ceil((rttMs - 25) / 50);
    for (int i = 0; i < ticks; i++) {
        dy = (dy - 0.08) * 0.98f;
        height += dy;
        if (height <= 0) return true;
    }
    return false;
}

Default horizontal and vertical scales are 1 and sprintVertical is 0. Thus an uncapped head-on sprint hit sends H=0.8544 before encoding; an unsprinted hit sends H=0.5274. Equal Y on those two hits is expected. Once capped, an additional fresh hit can set Y to zero even while the victim was falling. At zero added RTT the landing exception is off. For positive height up to 1.3 and added RTT above 25 ms, the predictor advances the last reported vertical delta using vy=(vy−0.08)×0.980000019… for up to ceil((RTT−25)/50) steps and checks for floor crossing. It uses measured report state and a configured delay. A predicted landing is a server rule, distinct from the victim’s actual ground collision.

The lab’s Hypixel-style preset uses the native-shaped fresh vector with a sprint-Y replacement of 0.07 at the default scales and a nine-tick window. Older lab MMC recordings tagged mmc_community_first_hit used a different sprint rule. Read the match’s combat_profile before applying the numbers above.

From a double to the victim’s next move

static short encodeAxis(double speed) {
    double clamped = Math.max(-3.9, Math.min(3.9, speed));
    return (short)(clamped * 8000); // Java truncates toward zero.
}

static short[] encodeVelocity(Vec v) {
    return new short[] { encodeAxis(v.x), encodeAxis(v.y), encodeAxis(v.z) };
}

static Vec decodeVelocity(short[] wire) {
    return new Vec(wire[0] / 8000.0, wire[1] / 8000.0, wire[2] / 8000.0);
}

S12 replaces all three components. A fresh head-on X of −0.5274 becomes −4219/8000 = −0.527375. An existing −0.2 is overwritten. A local contact before this overwrite scales the old speed; a contact after it scales the new one. If the player moves between those two events, the already-traveled distance stays traveled. A jump can overwrite Y and add a sprint impulse before travel if the grounded jump gate is open. A later S12 can overwrite that result. “Jump reset” therefore needs a specific order of jump, packet application, and movement to predict an outcome.

Why the two players see different reach

Your self position moves immediately on your movement tick. The opponent on your client is a replica. The server receives the opponent’s position reports, the tracker emits updates, and your client advances the replica toward its newest destination. In 1.8.9 ordinary tracked player positions are encoded on a 1/32-block grid. A relative update changes the accumulated destination. A new destination commonly requests three interpolation increments. Each remote-player tick moves a fraction of the remaining distance:

static Vec interpolateReplica(Vec current, Vec destination, int remainingSteps) {
    if (remainingSteps <= 0) return current;
    return new Vec(current.x + (destination.x - current.x) / remainingSteps,
                   current.y + (destination.y - current.y) / remainingSteps,
                   current.z + (destination.z - current.z) / remainingSteps);
}

A newer packet can replace the destination before the previous interpolation finishes. Neither “subtract half the ping” nor “both players use the last server tick” reconstructs those two local positions. Ordinary walking reports use position change squared >0.0009 or the 20-tick refresh gate; rotation-only and ground-only reports are possible. Tracker emission, packet arrival, game-thread drain and replica movement are distinct stages.

For ideal aim, use the standing eye at feet +1.62, a target box about 0.6 wide × 1.8 high, and the ordinary targeting border of 0.1 on each side. The nearest distance is the Euclidean length of the vector from the eye to its closest point on the expanded box. In actual play, the current look ray must intersect the eligible target within the ordinary three-block entity reach and beat nearer obstructions. At partial tick 1 the living look direction uses head yaw and pitch. Server acceptance also checks its own distance and line-of-sight rules before resolving damage.

static double eyeDistance(Vec eye, Box expanded) {
    double dx = Math.max(0, Math.max(expanded.x0 - eye.x, eye.x - expanded.x1));
    double dy = Math.max(0, Math.max(expanded.y0 - eye.y, eye.y - expanded.y1));
    double dz = Math.max(0, Math.max(expanded.z0 - eye.z, eye.z - expanded.z1));
    return Math.sqrt(dx*dx + dy*dy + dz*dz);
}

static double reachAdvantage(Vec myEye, Box theirBoxOnMyClient,
                             Vec theirEye, Box myBoxOnTheirClient) {
    return eyeDistance(theirEye, myBoxOnTheirClient) - eyeDistance(myEye, theirBoxOnMyClient);
}

What the server does with a walking report

The survival client ordinarily sends feet position and rotation when they change enough; each movement-report variant carries a ground bit. The server compares the request with its accepted position, checks speed and collision constraints, and can send a position correction. A grounded-to-air report with positive requested Y can trigger the server jump branch. Accepted descent and ground reports also feed fall distance, which matters for the next critical. This server state and the client’s post-travel motion can differ even at zero added ping.

static boolean startsServerJump(boolean wasGrounded, boolean reportedGround, double requestedDY) {
    return wasGrounded && !reportedGround && requestedDY > 0;
}

static int recordFall(Player serverPlayer, boolean reportedGround, double acceptedDY) {
    if (reportedGround) {
        int damage = Math.max(0, (int)Math.ceil(serverPlayer.fallDistance - 3f));
        serverPlayer.fallDistance = 0;
        return damage;
    }
    if (acceptedDY < 0) serverPlayer.fallDistance = (float)(serverPlayer.fallDistance - acceptedDY);
    return 0;
}

On a C02 attack, the native server distance guard uses squared player-position distance <36 with line of sight, <9 without. The normal local survival ray still determines whether an attack packet is produced. A report queued after the attack cannot change the server’s pose or sprint state for that attack retroactively.

What the techniques change

  • W-tapping changes forward acceleration and can re-arm the server sprint bonus. Check whether STOP and START arrived in time, and what spacing the release cost.
  • Hit selecting and mid-trade timing change which player is grounded, rising or falling at each contact and which return window is open. Taking a first hit and delaying your own can shift the two launch phases. Measure the next fresh window and the opponent’s ray to see who actually gained a return opportunity.
  • Burst clicking changes how many eligible local drag events fall between velocity application and travel. If one of them happens after movement, it can only affect later moves. If the underlying speed pointed forward, slowing it can shorten your chase.
  • Jump resetting changes the Y assigned before travel, the sprint-jump impulse, and when ground control returns. Use the ground flag and the ordered S12, jump and move records to distinguish an actual jump from being launched off the floor.

Reading another fight in replay

  1. Pause near the trade. In server POV, use hotbar 2 to step between hits, upgrades and KB records. Several records can share a millisecond. Note the vector, target, and whether the attack scored.
  2. Use the compass in slot 6 to follow the victim’s recorded POV, then use 2 to find the applied velocity and any local click drag. Match the entity, sign, magnitude and order. The clocks can put multiple events in one movement interval.
  3. Use 3 for native recorded ticks. Identify the starting ground flag, incoming motion, acceleration direction, actual displacement and outgoing motion. Repeat on the other POV. When a recording lacks a detailed event, the full pose/packet archive is the next source if available.
  4. At the return-hit window, compare each eye to its own replica of the other fighter. Check the actual ray and attack outcome separately. For an exact audit use full-precision logs; the step labels round H and Y for readability.
