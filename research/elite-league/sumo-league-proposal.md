# Single-match 7-CPS sumo league

Discussion plan, November 20, 2026. Two questions drive the experiment. Does remembering an opponent's earlier behavior help win the current duel? Can successive counters make a champion stronger across the field, including its worst matchup?

## One duel

Use the lab's current MMC range-calibrated preset, measured 137-block platform, gold spawns eight blocks apart, three-block reach and a physical cap of seven clicks per second for each player. Both get the same integer-mouse aim tracker and the existing zero added reaction delay, aim delay, noise and turn-rate-limit settings. Run the ordinary opening, with either seat equally likely. Draw the two RTTs independently per duel from integer 0–150 ms, reserve 31 and 109 ms for evaluation, and draw a recorded training clock independently of opponent identity. Fix RTTs during a duel. A ring-out gives +1 or −1. Simultaneous eliminations and 120-second timeouts give 0. No intermediate rewards. Report wins, losses and draws separately, even when ranking by wins plus half the draws.

One policy decision per local input tick, nominally 20 Hz. The proposed common input is 25 numbers. Use the 22 normalized observations from the shared controller (relative distance and height, own velocity, displayed opponent displacement, ground/sprint state, local hurt cues, center position, own RTT and previous applied controls). Append opponent RTT and its availability flag using the existing ping encoding, plus elapsed time since the last physical press using the existing timing encoding. Use the client-visible ping source and the missing-value encoding in both environments. The opponent's private inputs, identity and server state are unavailable to actor and critic. The five existing action scores choose forward/release/back, sprint with forward, left/neutral/right, allow/withhold attack, and grounded jump. All actions go through the normal movement, mouse and click scheduler, including misses. [Controller](../../src/lab/DuelNetwork.java) · [Timing feature](../../src/lab/SumoInputs.java)

## Learner

One 32-unit GRU, zero initial state on every spawn, standard sigmoid gates and tanh candidate, one bias per gate. Five linear action scores and one linear value estimate read the hidden state. Freeze weights during play. The GRU updates once per input tick and lives for exactly one duel. For the memory control, train a one-hidden-layer 180-unit softsign MLP. With the same 25 inputs and six outputs, both have 5,766 trainable parameters. The MLP gets the same short-term physical cues. The GRU alone can retain additional learned history.

Use PPO with the existing conditional action distribution at fixed temperature 0.25. Sample legal controls during training, tournaments and native play, with independent per-fighter randomness. Save the seeds for replay. Ground masks jump, and the sprint probability applies only to forward. Use the joint log probability of the applied choices. Adam at 0.00035, clipping at 0.18, gradient norm cap 0.6, gamma 1, GAE lambda 0.97, normalized advantages, value MSE weight 0.5, no extra entropy bonus. One update collects 64 complete duels, three passes, minibatches of eight duels. Shuffle whole duels, recompute recurrence from spawn with current weights, backpropagate through the whole duel, mask padding. Use the same optimizer, schedules and number of sampled duels for the MLP. The current PPO code shuffles individual ticks and needs this sequence path. Verify a small GRU gradient numerically, seeded Java inference and feature/action parity on recorded traces, hidden resets and unchanged continuation hashes before training. [Existing PPO](PPO.java)

## One league iteration

1. Freeze the incumbent and a registry of dated policies. Seed it with best-sumo, the 7-CPS counter that beat it 32–0, the 20-trained counter, plain W-tap, Hold-W and existing hit-select, jump-reset and strafe opponents. Add one training family of switch/stay sparring partners that choose between two of those behaviors after visible contact. Keep all historical winners eligible and playable. Freeze style-family labels, identical-policy aliases and train/development/evaluation clock manifests.
2. Train one **exploiter** for 256 updates (16,384 simulated duels) solely against the incumbent. Alternate starting it from scratch in odd generations and from the previous main learner in even generations, with fresh optimizer state and random seeds. Select the last checkpoint. Evaluate on 256 fresh development duels, balanced across both seats and four RTT pairs. Archive the exploiter as a confirmed counter if its one-sided 95% lower score bound exceeds 0.55. A failed search and its checkpoint are still recorded.
3. Train one **main** for 512 updates (32,768 simulated duels). Start the first main from scratch. Carry its training checkpoint forward every generation, independently of whether it earns the live title. Each duel has a 25% chance of facing the frozen incumbent, 25% of facing the newest confirmed counter, and 50% of facing the archive. Seed the counter slot with sumo-seven-first. In the archive draw, select a family uniformly half the time and proportional to (1 − mean main score against family)² + 0.05 otherwise, then draw a member uniformly. Use the previous development matrix, initialize unknown scores at 0.5 and hold the sampler fixed for that training block. Train the MLP control on the same generation's frozen opponent draws, seats and clocks, using independent action seeds. Add the final main and MLP checkpoints to the archive after evaluation. Save seeds, rollout counts, software hashes and every immutable policy.
4. Run a common development tournament among the incumbent, new learners and archived distinct winners, including a W-tap row and column. Play 256 simulated duels per new pairing, reusing existing cells only when the protocol is identical. Include scripted style families as opponents. Rank by the mean of two numbers, the equally family-weighted field score and the weakest-family score. Break ties by field score, then the incumbent, then immutable ID. Publish the actual tournament winner under a dated server name. Send the highest-ranked challenger to independent native confirmation only if it clears the simulation promotion criteria below. Keep each confirmed counter playable too. Share the existing CPU limiter (at most half the owner's cores across jobs) and main-server slots with the boxing work.

## What would count as learned adaptation?

First measure ordinary duels from spawn, including quick losses. Report the distribution of duel duration and fresh hits. Then test two unseen opponent variants with opposite exploitable habits, for example one that re-presses W immediately after a hit and one that consistently delays. On development variants, first verify via matched continuations that the better response actually reverses between the two habits. Freeze separate test variants and a switch-versus-stay opponent that can change habit once after a locally visible exchange. Hide the choice and switching rule from the learner.

Take one fork per eligible fight, immediately after the third observed hurt cue (either player). Save the whole game, both bots, input and network queues, clocks, feature caches and random streams. Check that an untouched fork reproduces the original actions and outcome. Change only the GRU hidden state in separate continuations. Compare the real state, zero state, and a donor state from the same or the opposite style. Match donors by seat, RTT, elapsed time (within 1 s), both hurt ages (within 100 ms), distance (within 0.25 blocks), grounded states and radial velocities (within 0.1 blocks/tick). Sample uniformly among eligible independent donors, exclude the source duel and report unmatched coverage. Teacher-force the same last ten recorded local input ticks and realized actions into each donor before resuming, so recent contact evidence is shared. Use donor states from ten ticks before their matched landmark matched on their original landmark observations. The recipient's actual physical state and all non-GRU caches remain identical. At a pre-cue control fork both styles use an identical observed opening, with the future style assigned independently. Test 256 matched recipient forks per held-out style and report all eligible and missing cases.

The primary contrast is correct-style versus opposite-style history on identical continuations, averaged equally over the two styles. Require a positive lower 95% bound and the predicted response reversal in both styles. Use the intact and erased comparisons to estimate practical value. Also compare full-duel GRU, MLP and W-tap in simulation and independent native bouts. Report the first changed move, its delay after visible evidence, the following trade and ultimate ring-out. Include never-switched and short games in the ordinary results. To test a possible information-gathering opening, allow or substitute the opening move, then preserve or erase what the bot remembers about the response. Look for a later payoff specific to retaining the observed response. Report any immediate positioning benefit separately. A stronger league bot and evidence of learned opponent adaptation are separate outcomes.

## Promotion and stopping

Use four evaluation RTT pairs in milliseconds, 31/31, 109/109, 31/109 and 109/31, each on both seats. Freeze one candidate and its native opponents before the confirmation starts. Compare candidate, incumbent and plain W-tap against the same opponents in simulation and on the server. The core native panel covers W-tap, frozen best-sumo, sumo-seven-first, the newest counter, the candidate's and incumbent's weakest historical families (one worst development representative per family), and two prospectively held-out styles. Deduplicate exact opponents. Include a direct challenger/incumbent matchup. Use 64 independent native scheduling blocks, each testing every arm/opponent once with the eight seat/ping cells rotated evenly. Randomize within blocks. Model comparison uses the same settings across arms and independent donor clocks, with a minimum of 32 donor clocks × eight cells. Native timings are independent realizations. Preserve invalid runs, replace under the same settings, and audit both clients' bindings and physical intervals. Report W/L/D, both seats, each RTT pair, the mean and worst family, every historical model matchup and native coverage. Run a matched 20/20 W-tap transfer check separately when changing the live title.

Promote best-sumo only when the model and native challenger both improve the incumbent's field mean or worst family, the other measure is within five percentage points of the incumbent, the challenger scores above 0.75 head-to-head against W-tap and outperforms the plain W-tap arm across the panel. For the first milestone, also require a score above 0.50 against sumo-seven-first. Use one-sided simultaneous 95% bounds on these contrasts, resampling whole independent timing donors or native blocks and recomputing the minimum across families. Use conservative bounded-score intervals for all-identical or sparse block contrasts. Analyze once at the frozen budget. If inconclusive, retain the incumbent and report the uncertainty. Seal fresh families/variants and clocks for each promotion, retire opened panels to development, and leave independent elite humans for the external grade. Nomophobia is development only.

Pause after three generations with neither promotion nor a new confirmed counter. Make one doubled-budget PPO best-response search with a fresh seed and a second search using the existing evolutionary optimizer at the same duel budget. As a positive control, verify the search still recovers a counter to the original vulnerable champion. Call it a plateau under this budget only if both final searches have a 95% upper score bound below 0.55 on independent evaluations and the positive control succeeds. Otherwise report the unresolved search, uncertainty or native transfer failure. The first milestone is a main that beats plain 7-CPS W-tap, closes the demonstrated frozen champion's weakness, and preserves its field performance.
