## Conditioning and causal boundary

The adapter supplies recorded player inputs and look angles, client movement/remote-update order, server entity/tracker boundaries, and packet task-service times. These are exogenous scheduler inputs. Packet payloads are generated by the kernel; the native payload is an assertion, never a state correction. A wrong generated packet or unsupported event stops strict replay and exposes the unexecuted tail.

Both player bodies, server bodies and replicas are seeded once at the settled initial position. Tracker counters, initial C03 report caches and report ages come from pre-start history. Initial `lastDamage` comes from the first pre-contact server snapshot after verifying that no earlier attack occurred: native setup may retain the prior duel's damage value even when immunity is zero. No later state is injected.

The m1203 first-divergence investigation showed why wire arrival alone is insufficient: a movement packet arrived about 0.014 ms before a server drain began, but its queued task was serviced on the following drain. Treating arrival as queue admission generated an extra replica. Using the actual task-service schedule resolves this divergence without changing the generated movement or replication payload. Future fixed-clock simulations must therefore vary enqueue/service timing, rather than treating one recorded schedule as universal.

The two new fixed-word native fixtures are held-out policy and longer-horizon checks. Their failures to maintain combos are reproduced under recorded inputs and task schedules. This isolates a limitation of nominal-clock controller predictions without attributing it to an unexplained transition mismatch. It does not establish impossibility under other feedback or schedules.

The independent fixed-clock adapter, `PeriodicComboClock`, calls the same transitions and explicitly models frame drains separately from movement ticks. Its phase and latency assumptions are hypothetical. Its aim generator is a convenient local perfect-aim policy; recorded replay uses the actual recorded look inputs. No policy may read the other true body or server state unless explicitly labeled an offline oracle experiment.

## Fresh windows and reach

The goal is defender local reach denial throughout maintenance, with our local target reachable at the fresh-damage opportunity. It does not require our reach continuously during immunity. Actual immunity crosses the native threshold on server entity updates, not necessarily 500 wall-clock milliseconds after a local contact. Accepted stronger-damage upgrades and fall damage must be distinguished from fresh melee hits. The kernel represents these transitions, including the configurable immunity threshold for fall damage.

The table verifies server immunity values at every recorded server snapshot and native selected-target decisions at the recorded click times. It does **not** separately claim exact timestamps for every first-ready opportunity between snapshots, numeric ray-intersection distances, or a counterfactual best send deadline under transport uncertainty. Those are separate evaluator obligations. A missed window at the end of a rollout must be counted or marked censored, rather than disappearing because no next hit completes.

Native fixed-word testing additionally shows that a nominal ten-client-tick attack interval can arrive at server H=11, one tick early. Re-anchoring on local contact alone does not resolve this: immune contacts apply local drag but do not reset target immunity. Received fresh-hurt cues are a useful next observation mechanism, but the kernel now transports native S19 status2 cues to both recipients. `Observation.lastTargetHurtTime()` and `lastOwnHurtTime()` expose only delivered cue times, initially negative infinity. Fresh fall damage can also emit status2, so a cue is not an infallible melee-only confirmation.

## Explicit limits

- Native degenerate knockback at horizontal separation below .01 uses a random direction. The kernel stops there rather than inventing a deterministic vector. Historical m1193 has an exact prefix through about 4326.7 ms and an unsupported tail; it is not a full pass. The eight fixtures above finish without this stop.
- S1C checks cover own sprint flags; unrelated metadata and S19 statuses other than hurt status2 are outside this version. Packet checks are exact for represented fields, not every byte of every native packet.
- Tracker forced teleport is implemented: its age advances only inside the eligible update branch and resets when age exceeds 400 or another teleport trigger fires. Native bytecode `lh.a` offsets347–354,608–652 establish the rule; a focused check exercises the gated age400/401 boundary. Replay seeds its initial age once from the initial tracker snapshot. The long-age boundary itself has source/boundary-test evidence, rather than a dedicated long native fixture.
- Flat open ground, two ordinary players, native walking/sprinting/strafe and modeled melee are the supported world. Arbitrary blocks, rods, inventory/world interactions and jumps supplied as controls are outside the current control adapter.
- Modified KB and hurt-time profiles need native profile-specific validation. Baseline agreement alone does not validate every modification.
- A finite search failure is neither physical impossibility nor limited-observation impossibility. A successful oracle branch is an existence hypothesis under its declared model/clock; it still needs native falsification and a legal observation-only controller.

## Branching API

`State.deepCopy()` clones every primitive scalar through `Object.clone`, then independently clones bodies, replicas, all packet buffers, transport assertion progress and latency arrays. Immutable `ExactTravel` records may be shared. `Clock.fork(policyA, policyB)` additionally copies pending clock events, sequence order, ticks, consumed controls, last-click times, timing configuration and combat configuration. Replacement policies must be fresh or immutable; an audit callback is deliberately detached. A control already consumed before a mid-tick fork remains active until that side's next input event.

`PeriodicComboForkCheck` checks all instance fields recursively, so newly added state fields enter the semantic comparison automatically. Fourteen branch points include input/movement/flush and server substeps. It checks identical continuation, independent mutation, transport cursor isolation, audit detachment and replacement-policy behavior. `PeriodicComboClockCheck` separately checks resting state, the exact first native sprint step and movement admission at an independent server drain. Forking is supported between `runUntil` calls, not from inside an event callback.
